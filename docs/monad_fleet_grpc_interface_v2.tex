\section{Document Purpose}
This document is a full, implementation-first specification of the currently deployed Monad Fleet device protocol profile.
It is intended for engineers building new device agents (Raspberry Pi or other Wi-Fi-capable devices) that must join the system and execute experiments safely.

The scope includes:
\begin{itemize}
  \item gRPC contract (\texttt{fleet.v2}),
  \item run lifecycle and idempotency,
  \item device-side persistence model,
  \item metrics forwarding pipeline (Prometheus/Mimir/Grafana),
  \item eLabFTW integration profile used by the running server.
\end{itemize}

\textbf{Implementation baseline:} February 23, 2026.
This document describes the behavior currently implemented in this repository, not a hypothetical future API.
\textbf{Canonical documentation note:} this file is the single source of truth for the Fleet device protocol profile.

\section{Audience, Scope, and Non-goals}
\textbf{Primary audience:}
\begin{itemize}
  \item engineers implementing a new device agent against \texttt{fleet.v2},

\section{Quick Start for New Device Integrators}
Use this path to bring a new device implementation online with predictable interoperability:
\begin{enumerate}
  \item \textbf{Generate gRPC stubs from the v2 proto.}
  Implement \texttt{fleet.v2.FleetManager} client calls from \texttt{fleet\_gateway\_v2.proto}.
  \item \textbf{Implement required identity behavior.}
  Persist a stable \texttt{agent\_id}. Do not generate a new identifier on every reboot.
  \item \textbf{Implement PREPARE loop.}
  \texttt{Hello} $\rightarrow$ \texttt{GetPolicy} $\rightarrow$ \texttt{AckPrepared}.
  Cache \texttt{policy\_id}; handle \texttt{NO\_WORK} and \texttt{NOT\_MODIFIED}.
  \item \textbf{Implement MEASURE execution.}
  Execute \texttt{CommandGroup.commands} in order with timeout/retry semantics.
  \item \textbf{Implement REPORT replay safety.}
  Persist run bundles locally and retry \texttt{PublishReport} until \texttt{ACCEPTED} or \texttt{DUPLICATE}.
  \item \textbf{Validate with smoke and verifier.}
  Run a real-device smoke flow and verify report acceptance, artifact linkage, and required metrics.
\end{enumerate}

\textbf{Minimal interoperability bar:}
\begin{itemize}
  \item correct handling of all required fields and enum statuses in this document,
  \item safe retry behavior for transient transport/server faults,
  \item local durability for unsent run reports.
\end{itemize}

\section{System Roles and Boundaries}
\subsection{Roles}
\begin{itemize}
  \item \textbf{Agent}: software on measurement device; executes policy and reports run results.
  \item \textbf{Monad Fleet}: orchestration service; resolves assignments, serves policy, ingests reports.
  \item \textbf{eLabFTW}: experiment registry and scheduler/event storage backend.
  \item \textbf{Metrics stack (optional)}: Prometheus + Mimir + Grafana.
\end{itemize}

\subsection{Boundary contract}
Agents communicate with Monad Fleet only.
Agents do \textbf{not} need eLabFTW-specific knowledge.
Backend routing (eLabFTW, time-series, object storage) is a server deployment concern.

\section{Architecture Overview}
\begin{verbatim}
Device Agent <-> gRPC fleet.v2 <-> Monad Fleet <-> eLabFTW API
          \-> optional HTTP ingest (/ingest/v1/metrics, /ingest/v1/artifacts)
                                           -> /metrics -> Prometheus -> Mimir -> Grafana
\end{verbatim}

\section{Transport and Endpoints}
\begin{itemize}
  \item gRPC transport: HTTP/2
  \item gRPC default port: \texttt{50060}
  \item reference client transport today: \texttt{grpc.insecure\_channel()} (no TLS)
  \item HTTP sidecar port: \texttt{9108}
  \item HTTP endpoints:
    \begin{itemize}
      \item \texttt{GET /healthz}
      \item \texttt{GET /metrics}
      \item \texttt{POST /ingest/v1/metrics}
      \item \texttt{POST /ingest/v1/artifacts}
    \end{itemize}
\end{itemize}

\textbf{Security note:} run on trusted LAN/VPN for this profile, or add mTLS in a hardened profile.

\section{Security and Trust Profile}
\subsection{Current deployment profile}
\begin{itemize}
  \item gRPC is plaintext (\texttt{grpc.insecure\_channel}) on trusted network segments.
  \item eLabFTW API credentials stay server-side; agents do not require eLabFTW API keys.
  \item Device trust is identity-based (\texttt{agent\_id}) and network perimeter-based.
\end{itemize}

\subsection{Production hardening profile (recommended)}
For deployments beyond trusted LAN/VPN boundaries, integrators \textbf{SHOULD} enable:
\begin{itemize}
  \item TLS for gRPC transport (preferably mTLS),
  \item network segmentation so only approved devices can reach Fleet gRPC,
  \item explicit credential rotation and revocation procedures for device identities,
  \item audit logging for assignment, acknowledgement, and report ingestion events.
\end{itemize}

\textbf{Security boundary rule:}
agents communicate only with Monad Fleet.
Any direct integration with eLabFTW APIs from device firmware is out-of-profile and not required for interoperability.

\section{Protocol Design Principles}
\subsection{Backend agnostic send operation}
The agent send operation is \texttt{PublishReport} (plus optional \texttt{PublishEvents}).
Reports carry:
\begin{itemize}
  \item structured events,
  \item artifact references,
  \item summary metrics.
\end{itemize}

This keeps the device contract generic while allowing server-side forwarding to different destinations.

\subsection{Forward compatibility}
\begin{itemize}
  \item Agents \textbf{MUST} ignore unknown fields and enum values.
  \item Servers \textbf{MUST} tolerate omitted optional fields.
  \item \texttt{Event.metrics} and \texttt{Report.summary\_metrics} are open extension maps.
\end{itemize}

\section{Service Definition}
Served package: \texttt{fleet.v2}. Service: \texttt{FleetManager}.

\begin{verbatim}
rpc Hello(HelloRequest) returns (HelloResponse);
rpc GetPolicy(GetPolicyRequest) returns (GetPolicyResponse);
rpc AckPrepared(AckPreparedRequest) returns (AckPreparedResponse);
rpc PublishReport(PublishReportRequest) returns (PublishReportResponse);
rpc PublishEvents(PublishEventsRequest) returns (PublishEventsResponse); // optional
\end{verbatim}

\section{RPC Contract Matrix}
\begin{longtable}{p{2.5cm}p{3.0cm}p{4.0cm}p{4.3cm}}
\textbf{RPC} & \textbf{Required request fields} & \textbf{Successful response pattern} & \textbf{Client action guidance} \\
\hline
\endhead
\texttt{Hello} &
\texttt{agent.agent\_id} &
gRPC success with \texttt{allowed\_mode}, poll hint, server metadata &
Call on startup and periodically on reconnect; refresh local control-plane assumptions from response. \\
\texttt{GetPolicy} &
\texttt{agent\_id} &
\texttt{OK}, \texttt{NOT\_MODIFIED}, or \texttt{NO\_WORK} &
Cache by \texttt{policy\_id}. Reuse cached policy on \texttt{NOT\_MODIFIED}. \\
\texttt{AckPrepared} &
\texttt{agent\_id}, \texttt{preparation\_id}, \texttt{policy\_id} &
\texttt{ACCEPTED} (including duplicate \texttt{preparation\_id}) &
Treat \texttt{REJECTED} as a control-plane failure; reacquire policy before measure. \\
\texttt{PublishReport} &
\texttt{report.run\_id} and agent identity &
\texttt{ACCEPTED} or \texttt{DUPLICATE} &
Retry identical report for transient failures; move run to sent on \texttt{ACCEPTED}/\texttt{DUPLICATE}. \\
\texttt{PublishEvents} &
\texttt{agent\_id} for live mode &
per-event ack list &
Optional in this profile; currently disabled by default and returns \texttt{REJECTED} acks. \\
\hline
\end{longtable}

\section{Run Lifecycle}
\subsection{Operational phases}
\begin{itemize}
  \item \textbf{PREPARE}: \texttt{Hello}, \texttt{GetPolicy}, \texttt{AckPrepared}
  \item \textbf{MEASURE}: local policy command execution on agent
  \item \textbf{REPORT}: \texttt{PublishReport}; optional \texttt{PublishEvents}
\end{itemize}

\subsection{Recommended loop}
\begin{verbatim}
1) Hello(agent descriptor)
2) repeat:
   a) GetPolicy(agent_id, last_policy_id)
   b) if NO_WORK: sleep(recommended_prepare_poll_sec)
   c) if NOT_MODIFIED: sleep(recommended_prepare_poll_sec)
   d) AckPrepared(...)
   e) execute command_groups
   f) PublishReport(run_id, events, artifacts, summary)
   g) on ACCEPTED or DUPLICATE: cache policy_id and continue
\end{verbatim}

\section{Control Plane Mode Semantics}
\subsection{Modes}
\begin{itemize}
  \item \texttt{RF\_SHARING}: expected for Wi-Fi-only devices.
  \item \texttt{DUAL\_NIC}: allowed only when Ethernet path is available and validated.
\end{itemize}

\subsection{Current server behavior}
\begin{itemize}
  \item Requesting \texttt{DUAL\_NIC} without Ethernet advertisement is downgraded to \texttt{RF\_SHARING}.
  \item \texttt{AckPrepared} rejects \texttt{DUAL\_NIC} when:
    \begin{itemize}
      \item \texttt{route\_verified=false}, or
      \item \texttt{control\_plane\_iface} is provided but is not Ethernet-like (\texttt{eth*}).
    \end{itemize}
\end{itemize}

\section{RPC Semantics}
\subsection{\texttt{Hello}}
\textbf{Required:} \texttt{agent.agent\_id}

\textbf{Purpose:}
\begin{itemize}
  \item register/refresh device presence,
  \item update descriptor metadata,
  \item negotiate effective control-plane mode.
\end{itemize}

\textbf{Important response fields:}
\begin{itemize}
  \item \texttt{allowed\_mode}, \texttt{mode\_reason}
  \item \texttt{recommended\_prepare\_poll\_sec}
  \item \texttt{server\_version}, \texttt{server\_time}, \texttt{max\_batch\_size}
\end{itemize}

\subsection{\texttt{GetPolicy}}
\textbf{Required:} \texttt{agent\_id}. Optional: \texttt{experiment\_id}, \texttt{last\_policy\_id}.

\textbf{Responses:}
\begin{itemize}
  \item \texttt{OK}: full \texttt{Policy} plus assignment context.
  \item \texttt{NOT\_MODIFIED}: \texttt{last\_policy\_id} still current, assignment context returned.
  \item \texttt{NO\_WORK}: no currently selected policy for this agent.
\end{itemize}

\subsection{\texttt{AckPrepared}}
\textbf{Required:} \texttt{agent\_id}, \texttt{preparation\_id}, \texttt{policy\_id}

\textbf{Validation:}
\begin{itemize}
  \item reject if no assigned policy,
  \item reject on policy revision mismatch,
  \item reject invalid \texttt{DUAL\_NIC} checks.
\end{itemize}

\textbf{Idempotency:}
duplicate \texttt{preparation\_id} is accepted and treated as already acknowledged.

\subsection{\texttt{PublishReport}}
\textbf{Required:}
\begin{itemize}
  \item \texttt{report.run\_id}
  \item agent identity from \texttt{agent\_id} or \texttt{report.agent\_id}
\end{itemize}

\textbf{Current server behavior:}
\begin{itemize}
  \item map v2 report/events into internal event model,
  \item write run state to eLabFTW scheduler event metadata,
  \item process artifact references as \texttt{ARTIFACT\_UPLOADED} events,
  \item export numeric summary/event metrics to \texttt{monad\_fleet\_metric\_value}.
\end{itemize}

\textbf{Status values:}
\begin{itemize}
  \item \texttt{ACCEPTED}
  \item \texttt{DUPLICATE} (same \texttt{run\_id|agent\_id|policy\_id})
  \item \texttt{REJECTED}
\end{itemize}

\subsection{\texttt{PublishEvents}}
In this deployment profile, live events are disabled (\texttt{ALLOW\_LIVE\_EVENTS=false}).
When disabled, each ack is \texttt{REJECTED} with reason \texttt{live events disabled}.

\section{Error Model and Retry Strategy}
\subsection{Transport-level gRPC status handling}
\begin{longtable}{p{3.4cm}p{5.0cm}p{4.8cm}}
\textbf{gRPC code} & \textbf{Typical cause in this deployment} & \textbf{Agent behavior} \\
\hline
\endhead
\texttt{INVALID\_ARGUMENT} & missing required request fields (for example empty \texttt{agent\_id}) &
Do not blind-retry. Fix request construction and log as implementation defect. \\
\texttt{INTERNAL} & unhandled server-side exception &
Retry with bounded exponential backoff + jitter. Preserve idempotency keys. \\
\texttt{UNAVAILABLE} / \texttt{DEADLINE\_EXCEEDED} &
network disruption, service restart, or timeout &
Treat as transient. Retry using backoff and keep local spool/replay intact. \\
\texttt{UNAUTHENTICATED} / \texttt{PERMISSION\_DENIED} &
possible in hardened profiles with authz/authn layers &
Stop and raise operator-visible configuration/security error. \\
\hline
\end{longtable}

\subsection{Application-level response status handling}
\begin{itemize}
  \item \texttt{AckPrepared.REJECTED}: reacquire policy and do not execute stale policy.
  \item \texttt{PublishReport.REJECTED}: keep run in pending spool and retry after backoff.
  \item \texttt{PublishReport.DUPLICATE}: treat as successful delivery outcome.
  \item \texttt{PublishEvents.EventAck.REJECTED}: do not fail the run lifecycle in this profile (live events are optional).
\end{itemize}

\subsection{Retry timing guidance}
\begin{itemize}
  \item Control-plane RPCs (\texttt{Hello/GetPolicy/AckPrepared}): start with 1-2s base delay and cap at 30-60s with jitter.
  \item Report replay (\texttt{PublishReport}): keep retrying until \texttt{ACCEPTED} or \texttt{DUPLICATE}; never drop unsent runs silently.
  \item Preserve the same idempotency identifiers across retries (\texttt{preparation\_id}, \texttt{run\_id}, \texttt{event\_id}).
\end{itemize}

\section{Idempotency and De-duplication}
\begin{itemize}
  \item prepare dedupe key: \texttt{preparation\_id}
  \item event dedupe key: \texttt{event\_id}
  \item report dedupe key: \texttt{run\_id|agent\_id|policy\_id}
\end{itemize}

Server runtime state is persisted at:
\begin{itemize}
  \item \texttt{/data/state.json} (container path)
\end{itemize}

\section{Data Model Reference}
\subsection{Common conventions}
\begin{itemize}
  \item Time on wire: \texttt{google.protobuf.Timestamp} in UTC.
  \item Policy JSON timestamps: ISO-8601 UTC (\texttt{Z} suffix).
  \item IDs are opaque strings; recommended:
    \begin{itemize}
      \item \texttt{agent\_id}: stable MAC or UUID
      \item \texttt{run\_id}: UUIDv4
      \item \texttt{event\_id}: UUIDv4 or deterministic hash
      \item \texttt{policy\_id}: server-generated immutable revision (\texttt{sha256:<digest>})
    \end{itemize}
  \item Numeric samples in maps are encoded as strings and parsed to float server-side.
\end{itemize}

\section{Policy Profile Used in This Deployment}
\subsection{Policy source}
Fleet policies are loaded from eLabFTW experiments tagged \texttt{fleet}.
Categories are not used by the fleet selector.

\textbf{Required authoring mode:}
store policy in experiment metadata JSON editor (not as attachment).

\textbf{Metadata keys searched in order:}
\begin{verbatim}
fleet.policy, policy, fleet_policy, policy_json
\end{verbatim}

\subsection{Selection logic}
\begin{itemize}
  \item candidate set: experiments with \texttt{fleet} tag
  \item optional tag matching by \texttt{RESOURCE\_TAG\_PREFIX} (default \texttt{device:})
  \item optional \texttt{target\_selector} on \texttt{device\_ids/device\_types/locations}
  \item newest modified valid policy wins
\end{itemize}

\subsection{Policy revision id}
Server canonicalizes policy JSON and computes:
\begin{verbatim}
policy_id = sha256:<digest>
\end{verbatim}

\subsection{Reference policy example}
\begin{verbatim}
{
  "fleet": {

\subsection{Policy JSON to \texttt{fleet.v2} mapping rules}
When policy is authored in eLabFTW metadata, the Fleet server maps JSON to proto with the following rules:
\begin{itemize}
  \item command type aliases:
    \begin{itemize}
      \item \texttt{type} or \texttt{command\_type} are accepted,
      \item unknown types are coerced to \texttt{SHELL}.
    \end{itemize}
  \item command timeout:
    \begin{itemize}
      \item use \texttt{timeout\_ms} when present and $>0$,
      \item otherwise derive from \texttt{timeout\_s} (default 60s).
    \end{itemize}
  \item retry mapping:
    \begin{itemize}
      \item \texttt{retry.max\_attempts} is total attempts including first try,
      \item legacy \texttt{retries=N} becomes \texttt{max\_attempts=N+1}.
    \end{itemize}
  \item command ordering:
    \begin{itemize}
      \item list form preserves list order,
      \item map form is sorted by \texttt{order} when provided.
    \end{itemize}
  \item \texttt{expected\_artifacts[*].path} and \texttt{path\_or\_glob} are both accepted.
\end{itemize}

\textbf{Interoperability recommendation:}
prefer explicit \texttt{timeout\_ms}, \texttt{retry.max\_attempts}, and ordered list-form \texttt{commands} to avoid ambiguous interpretation across client implementations.

\section{Device Persistence and Deferred Upload}
\subsection{Goal}
Preserve run outputs during network outages and retry upload later without data loss.

\subsection{Local spool layout}
\begin{verbatim}
DATA_ROOT/
  pending/<run_id>/
    context.json
    events.ndjson
    report.json
    artifacts/
      <command-id>-<timestamp>.log
      run-summary.json
  sent/<run_id>/
    ...same structure...
\end{verbatim}

\subsection{Upload semantics}
\begin{itemize}
  \item agent writes completed run bundle under \texttt{pending/<run\_id>/}
  \item agent retries \texttt{PublishReport} for pending runs
  \item on \texttt{ACCEPTED} or \texttt{DUPLICATE}, run is moved to \texttt{sent/<run\_id>/}
  \item sent history is pruned by \texttt{SENT\_RETENTION\_DAYS} (default 14)
\end{itemize}

\section{Artifact Handling Profile}
Artifacts are persisted locally first, then published through two layers:
\begin{itemize}
  \item \texttt{PublishReport} carries \texttt{ArtifactRef} metadata,
  \item optional HTTP upload (\texttt{POST /ingest/v1/artifacts}) sends local files to eLabFTW experiment uploads.
\end{itemize}

When HTTP artifact upload succeeds, agent rewrites artifact URI from local spool form to:
\begin{verbatim}
elabftw://experiments/<id>/uploads/<upload_id>
\end{verbatim}

If upload fails or is disabled, URI remains \texttt{spool://...} and run reporting still succeeds.

\subsection{Artifact bundling profile (current default)}
To reduce artifact fan-out per run, the agent bundles text artifacts before final report upload:
\begin{itemize}
  \item merge target: \texttt{.txt}, \texttt{.log}, \texttt{.json} (except \texttt{run-summary.json})
  \item bundle artifact name: \texttt{wifi-ble-csi-artifacts-bundle-<timestamp>.tar.gz}
  \item bundle contents:
    \begin{itemize}
      \item \texttt{entries/<original-files>}
      \item \texttt{manifest.json} (metadata only: name/checksum/size)
    \end{itemize}
  \item binary/raw capture outputs (for example CSI \texttt{.dat}) remain separate artifacts
  \item by default, merged source text files are deleted locally after bundle creation
\end{itemize}

Bundle controls:
\begin{itemize}
  \item \texttt{MERGE\_TEXT\_ARTIFACTS=true|false} (default \texttt{true})
  \item \texttt{MERGE\_TEXT\_ARTIFACTS\_DELETE\_SOURCES=true|false} (default \texttt{true})
\end{itemize}

With this profile enabled, a typical real Pi run publishes three primary artifacts:
\texttt{wifi-ble-csi-artifacts-bundle-*.tar.gz}, CSI binary output, and \texttt{run-summary.json}.

Relevant artifact classes for experiment analysis:
\begin{itemize}
  \item Wi-Fi: scan/link snapshots, command logs
  \item BLE: scan output snapshots, command logs
  \item CSI: capture logs, collector outputs, or reference notes
  \item run-level summary (\texttt{run-summary.json})
\end{itemize}

Current size guardrail:
\begin{itemize}
  \item server-side endpoint limit: \texttt{ARTIFACT\_MAX\_BYTES} (default 20 MiB)
  \item agent-side upload limit: \texttt{ARTIFACT\_UPLOAD\_MAX\_BYTES} (default 20 MiB)
\end{itemize}

\section{Metrics Pipeline Profile (v3)}
\subsection{Objective}
Store numeric Wi-Fi/BLE/CSI-derived metrics in time-series backend (Mimir) and visualize in Grafana.

\subsection{Path}
\begin{verbatim}
Agent summary/event metrics -> PublishReport -> Fleet /metrics -> Prometheus
                                                               -> remote_write -> Mimir -> Grafana
Low-resource sender JSON   -> /ingest/v1/metrics -> Fleet /metrics -> ...
\end{verbatim}

\subsection{Low-resource sender payload}
\begin{verbatim}
POST /ingest/v1/metrics
{
  "source": "embedded-board",
  "device_id": "lowlevel-board-01",
  "metrics": [
    {"name": "wifi_rssi_dbm", "value": -58.2},
    {"name": "ble_adv_count", "value": 81},
    {"name": "csi_frames_count", "value": 420}
  ]
}
\end{verbatim}
\textbf{Note:} this payload is optional for development/demo paths. Real-only smoke runs can disable synthetic injection entirely.

\subsection{Constrained board sender profile}
For room experiments, a constrained board (for example Arduino/ESP32) can publish numeric telemetry to Fleet without gRPC:
\begin{itemize}
  \item Wi-Fi boards (ESP32 class): post JSON directly to \texttt{/ingest/v1/metrics}.
  \item USB-only boards: emit newline JSON over serial and bridge on host with \texttt{scripts/arduino/serial\_to\_fleet\_ingest.py}.
\end{itemize}
Recommended payload identity fields:
\begin{itemize}
  \item \texttt{device\_id}: stable sender id (for example \texttt{esp32-room-01})
  \item \texttt{source}: sender class (\texttt{arduino-esp32}, \texttt{arduino-serial})
\end{itemize}
Reference assets in this repository:
\begin{itemize}
  \item \texttt{scripts/arduino/esp32\_fleet\_metrics\_sender.ino}
  \item \texttt{scripts/arduino/serial\_to\_fleet\_ingest.py}
\end{itemize}

\subsection{Metrics vs raw captures}
Mimir stores numeric samples, not binary capture blobs.
Therefore:
\begin{itemize}
  \item raw CSI/BLE/PCAP data should be persisted as artifacts (local/object storage and optionally mirrored to eLabFTW uploads)
  \item derived numeric metrics should be sent via event/summary maps
\end{itemize}
\textbf{Current deployment profile:} CSI numeric keys (\texttt{csi\_*}) are excluded from time-series export to Prometheus/Mimir/Grafana.
CSI remains artifact-first (run artifacts and optional eLabFTW uploads).

\section{eLabFTW Mapping Profile}
\subsection{Experiment authoring}
\begin{enumerate}
  \item create experiment
  \item add tag \texttt{fleet}
  \item store policy in metadata JSON (\texttt{fleet.policy})
  \item optionally use \texttt{device:<tag>} matching tags

\subsection{Device resources}
On first \texttt{Hello}, server ensures resource item exists for \texttt{Device <agent\_id>} and updates metadata.

\begin{itemize}

  \item \texttt{book\_max\_minutes=180}
  \item \texttt{book\_can\_overlap=1}
  \item \texttt{book\_is\_cancellable=1}
\end{itemize}
Typical runtime states include:
\begin{itemize}
  \item \texttt{ONLINE}
  \item \texttt{ASSIGNED}/\texttt{IDLE}
  \item \texttt{POLICY\_READY}/\texttt{POLICY\_CACHED}/\texttt{WAITING\_POLICY}
  \item \texttt{PREPARED}/\texttt{PREPARE\_REJECTED}
  \item \texttt{REPORT\_ACCEPTED}/\texttt{REPORT\_DUPLICATE}/\texttt{REPORT\_REJECTED}

Run aggregation key:
\begin{verbatim}

\end{verbatim}

\begin{itemize}

  \item \texttt{csi\_collector\_exit\_code}

\subsection{Interpretation notes}
\begin{itemize}
  \item \texttt{ble\_scan\_ok=1} means BLE scan command executed successfully; device discovery count may still be zero.
  \item \texttt{wifi\_scan\_ok=1} means Wi-Fi sensing produced usable evidence; in monitor-mode runs this can be true with \texttt{wifi\_connected=0}.
  \item set \texttt{REQUIRE\_WIFI\_CONNECTED=true} in verifier/smoke runs only when associated/station connectivity is an explicit acceptance requirement.
  \item \texttt{wifi\_avg\_rssi\_dbm} and \texttt{wifi\_link\_quality} are best-effort metrics based on available system tools.
  \item \texttt{wifi\_tx/rx\_bitrate\_mbps}, \texttt{wifi\_channel}, and interface counters provide richer Wi-Fi sensing context for RF/environment interpretation.
  \item \texttt{wifi\_sampling\_start\_jitter\_s\_applied}, \texttt{wifi\_sampling\_start\_wait\_epoch\_s\_applied}, and \texttt{wifi\_sampling\_preface\_sleep\_s\_applied} indicate how start de-synchronization was applied on sampled runs.
  \item \texttt{device\_*} metrics provide system-state context (thermal/load/memory/uptime) for cross-checking measurement stability.
  \item \texttt{wifi\_rssi\_sample\_index} tracks the latest sample ordinal within the configured sampling run.
  \item \texttt{csi\_frames\_total} may be zero if CSI collector is not configured or does not expose frame counts; check \texttt{csi\_collector\_configured} and \texttt{csi\_capture\_ok}.
  \item \texttt{csi\_capture\_disabled=1} indicates CSI execution was intentionally disabled by configuration (safety mode), not a collector failure.
\end{itemize}

\section{Implementation Profile Decisions}
\begin{itemize}
  \item \texttt{PublishEvents} is optional and disabled by default in this deployment.
  \item if report events are empty, server may synthesize summary run event.
  \item if \texttt{Event.event\_id} is missing, server may synthesize an id.
  \item metric forwarding target can change at Prometheus \texttt{remote\_write} without changing the device gRPC contract.
  \item this deployment sets \texttt{METRICS\_EXCLUDE\_PREFIXES=csi\_} on Fleet service, so CSI metrics are not exported to Grafana.
  \item artifact upload to eLabFTW is implemented through \texttt{/ingest/v1/artifacts}; upload can be disabled per-agent if needed.
  \item default Pi profile bundles text artifacts into \texttt{wifi-ble-csi-artifacts-bundle-*.tar.gz} and uploads CSI binary + run summary as separate artifacts.
  \item bundle manifest stores metadata only (no inlined artifact text payload fields); merged source text files are removed locally by default.
  \item sampled Wi-Fi runs throttle artifact fan-out by default (first+last sample artifact retention) to prevent oversized report processing on long sampling windows.
  \item agent-side report replay timeout is configurable via \texttt{REPORT\_RPC\_TIMEOUT\_S} and defaults to a higher value for Pi smoke runs.
  \item control-plane RPC timeouts can be tuned globally via \texttt{CONTROL\_RPC\_TIMEOUT\_S} or per method via \texttt{HELLO\_RPC\_TIMEOUT\_S}, \texttt{ASSIGNMENT\_RPC\_TIMEOUT\_S}, \texttt{POLICY\_RPC\_TIMEOUT\_S}, and \texttt{ACK\_PREPARED\_RPC\_TIMEOUT\_S}.
  \item CSI acquisition uses an external collector hook in this profile; collector integration is device/driver specific.
  \item smoke orchestration supports multi-Pi execution (\texttt{PI\_HOSTS\_CSV}, \texttt{AGENT\_IDS\_CSV}) with a single experiment targeting multiple device IDs.
  \item smoke-created experiment metadata can include RF room/scenario context (\texttt{fleet.rf\_context}) via \texttt{RF\_ROOM\_ID}, \texttt{RF\_SCENARIO\_ID}, and \texttt{RF\_RUN\_LABEL}.
  \item for Pi smoke runs, when \texttt{CSI\_COLLECTOR\_CMD} is unset the runner defaults to \texttt{sudo feitcsi --frequency 5240 --channel-width 80 --format VHT --output-file /tmp/csi.dat -v} with \texttt{CSI\_OUTPUT\_PATH=/tmp/csi.dat}.
  \item in strict real-data mode (\texttt{REAL\_DATA\_ENFORCE=true}, \texttt{REQUIRE\_REAL\_CSI=true}), smoke defaults \texttt{CSI\_REQUIRE\_EVIDENCE=true}, \texttt{CSI\_MIN\_FRAMES=REQUIRE\_CSI\_FRAMES\_MIN}, and \texttt{CSI\_MIN\_OUTPUT\_FILES=1} when not explicitly set.
  \item verifier supports optional \texttt{REQUIRE\_WIFI\_CONNECTED=true}; when unset/default, monitor-mode Wi-Fi evidence is accepted if \texttt{wifi\_scan\_ok=1}.
  \item Pi smoke runner applies a safety gate for Wi-Fi-only control-plane and can force \texttt{DISABLE\_CSI\_CAPTURE=true} unless \texttt{ALLOW\_WIFI\_DISRUPTIVE\_CSI=true}.
  \item sampled Wi-Fi live HTTP ingest is auto-disabled when Fleet route uses Wi-Fi (\texttt{wl*}); post-run/report replay remains enabled. Override via \texttt{ALLOW\_WIFI\_LIVE\_INGEST=true}.
  \item Pi smoke runner applies a CSI power-health preflight when \texttt{REQUIRE\_REAL\_CSI=true}; undervoltage/throttle states fail fast unless \texttt{CSI\_ALLOW\_THROTTLED=true}.
  \item very large CSI binaries should use object storage references when they exceed configured artifact limits.
\end{itemize}

\section{Third-Party Agent Conformance Test Plan}
Before onboarding a non-reference device agent, run at least the following tests:
\begin{enumerate}
  \item \textbf{Identity stability test}: reboot device and confirm \texttt{agent\_id} is unchanged.
  \item \textbf{Required field validation}: verify no control-plane call is sent with missing required IDs.
  \item \textbf{No-work polling}: verify \texttt{GetPolicy.NO\_WORK} respects poll interval backoff.
  \item \textbf{Policy cache test}: verify \texttt{GetPolicy.NOT\_MODIFIED} reuses cached policy.
  \item \textbf{Ack idempotency}: replay same \texttt{preparation\_id}; ensure server keeps \texttt{ACCEPTED}.
  \item \textbf{Report idempotency}: replay same \texttt{run\_id|agent\_id|policy\_id}; ensure \texttt{DUPLICATE}.
  \item \textbf{Offline replay}: disconnect network during report, then reconnect and confirm deferred upload succeeds.
  \item \textbf{Artifact linkage}: confirm published \texttt{ArtifactRef} entries appear in run history/eLab mapping.
  \item \textbf{Transport fault handling}: inject timeout/unavailable faults and verify bounded retry with no data loss.
  \item \textbf{Smoke verifier pass}: run real-device smoke profile and \texttt{scripts/rpi/verify\_real\_run.sh}.
\end{enumerate}

\textbf{Exit criterion for production onboarding:}
all mandatory conformance tests pass on the target hardware/OS image with the same configuration profile intended for operations.

\section{Integrator Checklist}
Before declaring a new device implementation production-ready, confirm:
\begin{enumerate}
  \item agent sends stable \texttt{agent\_id} and \texttt{Hello} metadata
  \item agent follows prepare/measure/report lifecycle with retries
  \item idempotency keys are implemented (\texttt{preparation\_id}, \texttt{run\_id}, \texttt{event\_id})
  \item transport-level and application-level failure handling follows Section ``Error Model and Retry Strategy''
  \item policy typed commands (\texttt{WIFI\_SCAN}/\texttt{BLE\_SCAN}/\texttt{CAPTURE\_CSI}) are handled or safely reported as unsupported
  \item run artifacts are persisted locally and published as \texttt{ArtifactRef.uri}, and optionally uploaded to eLabFTW via \texttt{/ingest/v1/artifacts}
  \item numeric metrics are exported via \texttt{summary\_metrics} and/or \texttt{event.metrics}
  \item network and transport security profile is explicitly selected (trusted LAN profile or hardened TLS profile)
  \item smoke test validates report acceptance, metrics visibility, and eLabFTW artifact uploads
\end{enumerate}
