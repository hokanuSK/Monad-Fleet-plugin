\section{Purpose}
This runbook defines the \textbf{current} real-data smoke flow for Raspberry Pi in this repository.
It is aligned with the implementation in:
\begin{verbatim}
scripts/smoke/v3_end_to_end_smoke.sh
scripts/rpi/smoke_test_agent.sh
scripts/rpi/verify_real_run.sh
\end{verbatim}

\section{Reality Profile (Current Deployment)}
\begin{itemize}
  \item Wi-Fi and BLE numeric metrics are exported to Prometheus/Mimir/Grafana.
  \item CSI is \textbf{artifact-first}: raw collector outputs are persisted/uploaded as artifacts.
  \item CSI metrics are intentionally excluded from Grafana in current compose profile:
\begin{verbatim}
METRICS_EXCLUDE_PREFIXES=csi_
\end{verbatim}
  \item Real CSI validation is done from run report + artifacts, not Grafana panels.
\end{itemize}

\section{Preconditions}
\begin{itemize}
  \item Raspberry Pi agent is deployed and reachable via SSH.
  \item Pi has tooling for real Wi-Fi/BLE collection (\texttt{iw}, \texttt{bluetoothctl}).
  \item CSI collector command is available if strict CSI is required (for example FeitCSI command).
  \item If strict CSI is required, \textbf{prefer Ethernet control-plane}.
\end{itemize}

\section{Strict Real-Data Gates}
The smoke script supports strict gates:
\begin{verbatim}
REAL_DATA_ENFORCE=true
REQUIRE_REAL_WIFI=true
REQUIRE_REAL_BLE=true
REQUIRE_REAL_CSI=true
REQUIRE_CSI_FRAMES_MIN=1
\end{verbatim}

When strict mode is enabled:
\begin{itemize}
  \item hypothetical metric injection is forced off,
  \item run fails if expected Wi-Fi/BLE/CSI evidence is missing,
  \item run fails if CSI is required but collector command is not configured.
\end{itemize}

\section{Control-Plane Safety}
If route to Fleet Manager is over Wi-Fi (\texttt{wl*}), active CSI may break SSH/control-plane.

Implemented behavior:
\begin{itemize}
  \item default safety: CSI disabled in Wi-Fi-route cases (\texttt{DISABLE\_CSI\_CAPTURE=true}),
  \item strict CSI mode (\texttt{REQUIRE\_REAL\_CSI=true}) fails fast on Wi-Fi-route unless explicitly overridden,
  \item override switch: \texttt{ALLOW\_WIFI\_DISRUPTIVE\_CSI=true} (use only if SSH drops are acceptable).
\end{itemize}

\section{Reference Strict Run Command}
\begin{verbatim}
RUN_PI=true PI_HOST=monad-rpi5.local \
SMOKE_PROFILE=wireless_spec \
WIRELESS_SPEC_DURATION_S=30 WIRELESS_SPEC_INTERVAL_S_PI=5 \
REAL_DATA_ENFORCE=true REQUIRE_REAL_WIFI=true REQUIRE_REAL_BLE=true \
REQUIRE_REAL_CSI=true REQUIRE_CSI_FRAMES_MIN=1 \
INJECT_HYPOTHETICAL_METRICS=false \
CSI_COLLECTOR_CMD='sudo feitcsi --frequency 5180 --channel-width 80 --format HESU \
  --output-file /tmp/csi.dat -v' \
CSI_OUTPUT_PATH=/tmp/csi.dat \
scripts/smoke/v3_end_to_end_smoke.sh
\end{verbatim}

\section{What Is Verified}
During/after smoke run:
\begin{itemize}
  \item a new eLabFTW experiment is created (existing user data unchanged),
  \item Pi executes policy one-cycle and publishes report,
  \item Prometheus/Mimir queries confirm Wi-Fi/BLE metrics,
  \item eLabFTW uploads are listed for the created experiment,
  \item \texttt{scripts/rpi/verify\_real\_run.sh} checks report summary + event evidence + artifact classes.
\end{itemize}

\section{Expected Outputs}
\begin{itemize}
  \item eLabFTW experiment ID printed at end of smoke run,
  \item Grafana URL:
\begin{verbatim}
http://localhost:3000
\end{verbatim}
  \item verifier output includes:
\begin{verbatim}
RUN_ID=<uuid>
REAL_DATA_CHECK=PASS
\end{verbatim}
  \item if evidence is missing, verifier exits non-zero and prints failing criteria.
\end{itemize}

\section{Known Limitation}
Intel AX210 with stock driver does not provide CSI by itself.
Strict CSI success requires a working collector/driver integration on Pi.
Without that integration, strict mode correctly fails with collector/capture evidence errors.
