## Generate Bundles

On macOS, if `wg` is not installed locally, use the EC2 host as the keygen
helper:

```bash
WG_KEYGEN_SSH=ladamik@34.198.184.128 \
  scripts/rpi/generate_wireguard_flash_bundle.sh
```

The output is written under:

```text
artifacts/output/rpi-wireguard-flash/<timestamp>/
```

Private keys are under gitignored `artifacts/`. Treat the generated output as
secret material until each SD card has booted once.

## Add EC2 Peers

The generator writes `server_apply_peers.sh`. Copy it to EC2 and run it
interactively so `sudo` can prompt:

```bash
scp artifacts/output/rpi-wireguard-flash/<timestamp>/server_apply_peers.sh \
  ladamik@34.198.184.128:/tmp/monad-add-wg-peers.sh

ssh -t ladamik@34.198.184.128 'bash /tmp/monad-add-wg-peers.sh'
```

The script appends missing peer blocks, hot-adds peers with `wg set`, and does
not bounce `wg0`.

## Flash Ubuntu Server 24.04 LTS

Use Raspberry Pi Imager to flash **Ubuntu Server 24.04 LTS 64-bit**. In Imager
advanced settings, configure:

- SSH enabled with your public key
- the OS user you want to use later (`admin` or `monad`)
- Wi-Fi/LAN settings for the same network as the existing Monad Pis

After flashing, leave the SD card mounted. Apply the matching bundle to the
FAT boot partition:

```bash
scripts/rpi/apply_ubuntu_wireguard_boot_bundle.sh \
  artifacts/output/rpi-wireguard-flash/<timestamp>/monad-03 \
  /Volumes/system-boot
```

Repeat with the matching device directory for every new card.

The Ubuntu applier preserves the existing cloud-init `user-data` generated by
Raspberry Pi Imager and adds a second cloud-init part that installs and enables
WireGuard. It also copies `monad-wireguard.env` to the boot partition; this file
contains the device private key and is deleted by the Pi after successful
provisioning.

For Raspberry Pi OS instead of Ubuntu, use:

```bash
scripts/rpi/apply_wireguard_boot_bundle.sh <device-dir> <boot-volume>
```

## First Boot Behavior

On first boot, the Pi:

1. Sets the hostname.
2. Installs a one-shot provisioning service.
3. Reboots once.
4. Installs `wireguard` / `wireguard-tools` after networking is online.
5. Writes `/etc/wireguard/wg0.conf`.
6. Enables `wg-quick@wg0`.
7. Deletes the private-key payload from the boot partition.

Logs:

```text
/var/log/monad-wireguard-firstrun.log
/var/log/monad-wireguard-provision.log
```

## Rename Existing `.13` Device To `monad-04`

Do this on the device that is currently known as `monad-03` and already uses
`10.200.0.13`:

```bash
ssh -J ladamik@34.198.184.128 <pi-user>@10.200.0.13
sudo hostnamectl set-hostname monad-04
sudo sed -i 's/^127\.0\.1\.1.*/127.0.1.1 monad-04/' /etc/hosts
sudo reboot
```

No WireGuard IP change is needed for that device. On EC2, the peer comment can
be renamed later for clarity, but routing is controlled by the public key and
`AllowedIPs = 10.200.0.13/32`.
